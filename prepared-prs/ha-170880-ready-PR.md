## Summary

The IntesisHome integration (`homeassistant/components/intesishome/`) broke in Home Assistant **2026.5.2** after dependency `pyintesishome` was bumped from **1.8.0 → 1.8.7** in PR [#170382](https://github.com/home-assistant/core/pull/170382).

The root cause is an **API incompatibility**: in `pyintesishome` 1.8.0, `add_update_callback()` was an `async def` method, but in 1.8.7+ (including 2.0.0) it was refactored to a synchronous `def`. However, the HA integration code still calls it with `await`, causing a runtime error.

A community member (@SeitzDaniel) posted a working fix in their fork at https://github.com/SeitzDaniel/intesishome, but did not know how to submit a PR to the official repo.

---

## Root Cause Analysis

### The Bug

File: `homeassistant/components/intesishome/climate.py`, line 213:

```python
await self._controller.add_update_callback(self.async_update_callback)
```

**In pyintesishome 1.8.0:**
```python
async def add_update_callback(self, method):
    self._update_callbacks.append(method)
```
→ `await` was correct.

**In pyintesishome 1.8.7+ / 2.0.0:**
```python
def add_update_callback(self, method):
    self._update_callbacks.append(method)
```
→ `await` on a non-async function raises `TypeError` / `RuntimeWarning`.

The method only appends to a list — it never performs any I/O — so making it synchronous was a sensible cleanup in the library, but the HA integration wasn't updated to match.

### What the user sees

- Integration fails to load after upgrading to HA 2026.5.2
- Log shows a "compilation error" or `TypeError` related to `await` on a non-coroutine
- Integration worked fine with `pyintesishome==1.8.0`

**Explanation:**
- `from __future__ import annotations` is added (standard HA best practice for Python 3.14+ compatibility, present in most HA integration files).
- `await` is removed from `add_update_callback()` because it is no longer an async method in pyintesishome 1.8.7+ / 2.0.0.

### 2. `homeassistant/components/intesishome/manifest.json` — Bump dependency to 2.0.0

```diff
-  "requirements": ["pyintesishome==1.8.7"]
+  "requirements": ["pyintesishome==2.0.0"]
```

**Explanation:** Version 2.0.0 of pyintesishome includes significant improvements over 1.8.7:
- Proper SET acknowledgment tracking with seqNo-based correlation (`_set_value` now waits for ACK)
- Robust auto-reconnect lifecycle (`_handle_disconnect` hook, `_close_writer`)
- Many crash fixes and `None` guards
- Protocol cleanup and code quality improvements

The HA integration API surface is fully compatible (same exports: `IntesisHome`, `IHAuthenticationError`, `IHConnectionError`).

### 3. `requirements_all.txt` — Update global requirements manifest

## Verification

### The fix is correct because:

1. **Method signature confirmed**: `add_update_callback` is defined as `def` (sync) in pyintesishome `intesisbase.py:670` for both v1.8.7 and v2.0.0:
   ```python
   def add_update_callback(self, method):
       """Public method to add a callback subscriber."""
       self._update_callbacks.append(method)
   ```

2. **No other breaking changes**: All other methods used by the HA integration (`poll_status`, `connect`, `stop`, `set_mode`, `set_temperature`, `get_devices`, etc.) have the same signatures in 1.8.7 and 2.0.0. The `__init__.py` exports (`IntesisHome`, `IHAuthenticationError`, `IHConnectionError`) are unchanged.

3. **Confirmed working**: @SeitzDaniel has tested this fix in their own HA instance.

### Additional testing notes:

- The `from __future__ import annotations` addition is not strictly required for this fix (HA requires Python 3.14+ which has PEP 649 lazy evaluation), but it's consistent with HA code style and was included in the tested fix.
- There are **no existing tests** for the intesishome integration (`tests/components/intesishome/` does not exist), so no test changes are needed.
- After applying changes, run `python -m script.hassfest --action validate` to verify manifest.

## Alternative Considered: Simple Revert to 1.8.0

A simpler fix would be to revert `pyintesishome` from 1.8.7 back to 1.8.0 in both `manifest.json` and `requirements_all.txt`, without changing `climate.py`. 

**However**, this is **not recommended** because:
- The `await` bug exists in both 1.8.7 and 1.8.0? No — actually 1.8.0 has `async def add_update_callback`, so reverting alone would also work.
- But staying on 1.8.0 would lose many important bugfixes and improvements in 2.0.0.
- The proper fix (remove `await` + bump to 2.0.0) is more maintainable long-term.

**Recommended approach: Fix the `await` bug AND bump to 2.0.0.** This is what @SeitzDaniel tested and confirmed working.
