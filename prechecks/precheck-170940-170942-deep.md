### ① Issue 是否真实明确？

🟢 **明确** — 用户清晰描述了问题场景：

用户使用 LocalAI（兼容 Ollama API 的替代后端）通过 HA Ollama 集成聊天。问题：
1. 在模型选择 UI 中填写自定义模型名（如 `qwen3.5-9b`，不在 `MODEL_NAMES` 列表中）时，HA 自动追加 `:latest` 后缀
2. 模型不在"已下载"列表时，HA 自动调用 `client.pull()` 尝试下载
3. LocalAI 不支持 `pull()` 操作，导致失败
4. 用户需要一个选项来跳过下载流程，直接使用已存在的模型

**根因定位（代码层面）**：

| 问题 | 代码位置 | 具体逻辑 |
|------|---------|---------|
| `:latest` 追加 | `config_flow.py` line ~196 | `f\"{m}:latest\"` 对不在 `MODEL_NAMES` 的模型不适用，但 `custom_value=True` 允许输入任意值后仍被追加 |
| 强制下载 | `config_flow.py` ~line 220-225 | `if self._model not in currently_downloaded_models:` → 触发 `async_step_download()` → `self._client.pull()` |

**关键代码观察**：
- `MODEL_NAMES` 在 `const.py` 中硬编码了约 130 个已知模型名
- `async_step_set_options` 构建的 `models_to_list` 列表：已下载模型（精确名） + 已知模型（追加 `:latest`）
- 用户输入的自定义模型名（不在 `MODEL_NAMES` 中）不会被 `:latest` 污染，但仍然会因为不在 `currently_downloaded_models` 而触发下载

### ① Issue 是否真实明确？

🟢 **明确** — 用户提供了完整复现步骤和详细描述：

**复现步骤**：
1. 通过 HA UI 移除 Google Home fabric
2. 从 HA Matter 集成中删除设备
3. 对物理设备执行恢复出厂设置（按住 10 秒）
4. 重启 Matter Server Add-on
5. 重启 Home Assistant Core（刷新实体注册表）
6. 重新通过 HA Companion App 配对设备

**预期行为**: 设备应作为全新实例配对，生成新的实体 ID

**实际行为**: HA 立即识别硬件证书并恢复旧设备配置和命名约定

**根本原因分析（代码层面）**：

HA Matter 集成的设备标识链：
```
Matter Node → Endpoint → get_device_id(server_info, endpoint)
  → f"{operational_instance_id}-{postfix}"
  → operational_instance_id = f"{fabric_id_hex}-{node_id_hex}"
```

| 组件 | 角色 | 问题 |
|------|------|------|
| `helpers.py:get_device_id()` | 生成 HA device ID | 基于 fabric_id + node_id + endpoint_id |
| `helpers.py:get_operational_instance_id()` | 生成操作实例 ID | fabric 变化后 ID 不同 |
| `adapter.py:_create_device_registry()` | 创建/更新 device registry 条目 | 使用 hardware certificate 中的 serial number 作为第二标识 |
| `adapter.py:node_removed_callback()` | 节点移除时的清理 | 只处理 `endpoint_removed_callback` 但不会阻止重新配对时的恢复 |
| `__init__.py:async_remove_config_entry_device()` | 用户删除设备的入口 | 调用 `matter_client.remove_node()` 但不会在 HA 侧标记"已遗忘" |

**核心问题**：即使从 Matter fabric 中移除了节点、清除了设备注册表条目，重新配对时，Matter server 会为同一硬件设备分配新的 node_id，但由于 HA 的 discovery 逻辑（`_setup_node` → `_setup_endpoint` → `_create_device_registry`）基于端点标识创建新的注册条目，旧的条目可以被覆盖恢复。关键问题是 **HA 的实体注册表在删除设备时没有清除"已删除"标识，导致重新发现时恢复旧状态**。
